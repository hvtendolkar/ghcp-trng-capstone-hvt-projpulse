## FAQ Quick Answers

**Q: Do I need to follow governance?**  
A: Yes. Governance applies to all code merged to main.

**Q: What if my PR violates governance?**  
A: Reviewer identifies issue, you fix it, then merge. Learning opportunity!

**Q: How long does adoption take?**  
A: You can start immediately. Target 30 days for full team adoption.

**Q: What if I have questions?**  
A: Read [FAQ.md](docs/governance/FAQ.md) or ask your Tech Lead.

**Q: Can governance change?**  
A: Yes! Follow [Amendment Process](docs/governance/amendment-process.md) to propose changes.

## Governance in Action

### For Developers
```
1. Read: [Developer Onboarding](docs/governance/developer-onboarding.md)
2. Checklist: Use [Pre-PR Checklist](docs/governance/developer-pre-pr-checklist.md) before submitting
3. PR: Create PR using template (governance checklist auto-included)
4. Review: Provide feedback on governance, merge when compliant
```

### For Reviewers
```
1. Read: [Reviewer Procedures](docs/governance/reviewer-procedures.md)
2. Check: Apply [General Governance Checklist](specs/001-project-governance/contracts/general-governance-checklist.md)
3. Request: Changes if violations found
4. Approve: When governance checklist passed
```

### For Leadership
```
1. Read: [Constitution Overview](docs/governance/constitution-overview.md)
2. Monitor: Monthly compliance audits
3. Support: Enforce governance adoption
4. Track: Compliance rate trend (target 95%+)
```

## Governance Success Metrics

Track these metrics monthly:

- **Adoption**: % of team with governance acknowledgment (target: 100% by Oct 28)
- **Compliance**: % of PRs meeting governance standards (target: 95%+)
- **Violations**: Count and severity of non-compliant PRs
- **Code Quality**: Trend in test coverage and bug rate
- **Review Time**: Time to governance review completion

View monthly compliance audit reports in [`COMPLIANCE/monthly-audits/`](COMPLIANCE/monthly-audits/)
